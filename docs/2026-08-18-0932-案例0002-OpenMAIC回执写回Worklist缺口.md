# 案例 0002：OpenMAIC 回执写回 CaseWorklist 缺口

更新时间：2026-08-18 09:32 +08:00

## 当前阶段

案例 0002 现在的生产顺序已经固定为：

```text
0002-020 storyboard request
→ 0002-025 无配图 storyboard PPTX
→ 0002-027 用户审批
→ 0002-030/040/050 REAL 图片与绑定
→ 0002-055 带配图 storyboard PPTX
→ 0002-057 用户审批
→ 0002-060 REAL 视频
```

`0002-025` / `0002-055` 都必须使用 go-tool 注册能力 `presentation.openmaic`，真正成果由 `liuxb99/openmaic-fork` 的正式 Operator Action 在 assigned host 上生成。

## 本轮发现的接口缺口

OpenMAIC Action 的机器回执权威结构为：

```json
{
  "tool": "presentation.openmaic",
  "status": "succeeded",
  "artifact": {
    "path": "...",
    "size_bytes": 123,
    "slide_count": 4,
    "sha256": "...",
    "media_count": 0
  },
  "manifest": "...",
  "runner": {
    "computer_name": "DESKTOP-ODAQN0D"
  }
}
```

但 CaseWorklist 的验收键是：

- `0002-025`: `storyboard_pptx / storyboard_manifest / storyboard_pptx_sha256 / slide_count / reopen_receipt / image_count`
- `0002-055`: `illustrated_storyboard_pptx / illustrated_storyboard_manifest / illustrated_storyboard_sha256 / slide_count / reopen_receipt / bound_image_count`

因此不能直接把整个 OpenMAIC JSON 当 evidence，也不能靠 workflow 自己随意拼字段。需要 OpenWorker 拥有一个确定性 adapter，把 owning tool receipt 转成 CaseWorklist acceptance evidence，并在写回前执行阶段专属验收。

## P0 修复

新增 `scripts/case0002_apply_openmaic_receipt.py`，职责只做以下事情：

1. 只接受 step `0002-025` 或 `0002-055`。
2. 验证 receipt `tool == presentation.openmaic`、`status == succeeded`。
3. 验证 runner `computer_name` 等于 durable Worklist `assigned_host`。
4. 验证 artifact path 位于 durable Worklist `workspace_root` 内。
5. 验证 artifact `slide_count > 0`、`sha256` 非空、manifest 非空。
6. `0002-025` 强制 `media_count == 0`。
7. `0002-055` 强制 `media_count > 0`。
8. 将 receipt 权威字段映射到当前 step 的 acceptance keys。
9. 先 record evidence，再 complete `presentation.openmaic` action，最后 PASS step。
10. 任一验证失败都 fail-closed，不得改变 step 为 PASS。

## 第一阶段映射

```text
artifact.path       → storyboard_pptx
manifest            → storyboard_manifest
artifact.sha256     → storyboard_pptx_sha256
artifact.slide_count→ slide_count
receipt             → reopen_receipt
artifact.media_count→ image_count
```

## 第二阶段映射

```text
artifact.path       → illustrated_storyboard_pptx
manifest            → illustrated_storyboard_manifest
artifact.sha256     → illustrated_storyboard_sha256
artifact.slide_count→ slide_count
receipt             → reopen_receipt
artifact.media_count→ bound_image_count
```

## 重要边界

这个 adapter 不生成 PPTX、不运行 OpenMAIC、不猜 workspace、不扫描“最新文件”。它只消费 owning tool 已产生的机器回执，并把权威结果写回 OpenWorker CaseWorklist。

`0002-025` 完成后 canonical next 必须变成 `0002-027` 并停止，等待用户批准；绝不能自动继续图片阶段。
