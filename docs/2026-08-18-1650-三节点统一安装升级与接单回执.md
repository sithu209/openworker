# OpenWorker 三节点统一安装升级与接单回执

时间：2026-08-18 16:50 Asia/Taipei

## 目标

UL7、O87、ODA 三台电脑都必须安装 OpenWorkerNode，都必须能由同一套流程升级，而且必须用机器自己产生的回执证明“已接单”和“已升级成功”。不能再把 Git trigger 当成成功证据，也不能依赖 ChatGPT/GitHub connector 是否能列出 push workflow run。

固定机器：

- UL7：DESKTOP-UL7V2VV
- O87：DESKTOP-O87PJNR
- ODA：DESKTOP-ODAQN0D

## 新统一入口

`.github/workflows/upgrade-openworker-nodes-v2.yml`

触发方式：workflow_dispatch，或 main push 的 commit message 含 `[upgrade-openworker-nodes-v2]`。

一次触发产生三个独立固定 runner job：UL7、O87、ODA。每个 job 都会执行：checkout → 固定电脑名称检核 → ACCEPTED 回执 → Go build → 安装/升级 Windows OpenWorkerNode 服务 → `/v1/node/status` 权威验证 → VERIFIED 回执。

## 接单证据

runner 真正开始执行后立即写：

`case-evidence/node-upgrade/<target-sha>/<node>-accepted.json`

内容至少包含 machine、runner_name、target_commit、accepted_at。没有该文件，不能宣告该机器已经接单。

## 升级成功证据

服务安装/升级后读取本机 `http://127.0.0.1:8787/v1/node/status`，必须满足：

- `service.running_commit == target_commit`
- `service.target_commit == target_commit`
- `service.upgrade_verified == true`
- `service.upgrade_status == VERIFIED`

满足后才写：

`case-evidence/node-upgrade/<target-sha>/<node>-verified.json`

因此状态定义为：

- 无 accepted receipt：DISPATCHED / NOT ACCEPTED
- 有 accepted、无 verified：ACCEPTED / UPGRADING 或 FAILED
- 有 verified 且 commit 一致：VERIFIED

## 架构结论

OpenWorker 的三台 Windows 电脑现在统一视为正式 Node。安装、升级、接单、版本自证必须使用同一份 contract；案例能力差异只保留在 capabilities，不再影响节点基础设施生命周期。
