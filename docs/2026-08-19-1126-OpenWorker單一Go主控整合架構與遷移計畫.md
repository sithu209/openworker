# OpenWorker 單一 Go 主控整合架構與遷移計畫

更新時間：2026-08-19 11:26 +08:00

## 1. 決策摘要

OpenWorker 後續不再維持「多個主控程式 + 多個 Case 專用 Python controller」的架構。

正式收斂為：

**一個 Go 可執行檔 `openworker.exe` + 一套 Go package + 一個 durable authority / Case Engine。**

Python 不再屬於主控 runtime。Python 僅允許存在於真正需要 Python 生態的 leaf capability，例如 ComfyX、OpenMAIC、Blender Python、既有 AI/資料處理 adapter。

因此未來 canonical 控制鏈為：

`ChatGPT / llama.cpp / OpenCode -> openworker.exe -> Go Case Engine -> Go durable queue -> Go worker/executor -> leaf capability`

GitHub Actions 僅作 transient command transport / deployment，不得成為 business execution authority。

---

## 2. 為什麼現在必須整合

目前控制責任分散在：

- `openworkerctl.exe`
- go-tool local supervisor `:8848`
- OpenWorker node `:8787`
- `coworker.case0005_controller`
- `coworker.case0005_logged_controller`
- `coworker.case0005_verified_local_controller`
- `coworker.case0005_true_local_controller`
- 其他 Case 0005 lifecycle / recovery / fanout Python mixin
- PowerShell transport/install/diagnose scripts

Case 0005 最新真實失敗已證明這種分層過多會增加不必要的 runtime 風險：OpenWorker durable job 已建立，但 Python controller 入口尚未真正執行前，Windows stderr 即回報 CP950「找不到網路路徑。」。

主控不應因 Python module path、Python 版本、cwd、service account、PATH、virtualenv、shell quoting 等因素而無法啟動。

## 3. 最終目標

### 3.1 唯一可執行檔

正式入口：

`openworker.exe`

預定命令：

```text
openworker supervisor status
openworker supervisor recover

openworker case bootstrap 0005
openworker case continue 0005
openworker case status 0005
openworker case diagnose 0005
openworker case retry 0005

openworker queue status
openworker queue clear
openworker queue drain

openworker capability invoke <allowlisted-action>
```

### 3.2 `openworkerctl.exe`

遷移期保留，但只是一個 compatibility shim，共用同一個 Go `controlcli` package，不再維護第二套控制邏輯。

完成遷移後可移除。

### 3.3 Go Case Engine

通用 Case Engine 不為 Case 0005 寫死流程，而是讀：

- `case-worklists/<case_id>.json`
- `case-specs/<case_id>.json`

Case 0005 只是第一個完整 migration / REAL verification 案例。

後續 Case 0002 / 0003 / 0004 直接使用同一個 Go Engine。

## 4. 權威邊界

### Go 主控負責

- Case bootstrap
- worklist/spec parsing
- dependency DAG
- ready-step scan
- status transition
- acceptance gate
- durable dispatch
- idempotency
- retry/cancel
- queue clear/drain
- ledger append/query/reconcile
- process status
- fanout coordinator
- join coordinator
- artifact metadata/provenance orchestration
- fixed-machine routing
- local supervisor health gate
- failure diagnosis

### Python 僅負責 leaf capability

例如：

- `comfyx-studio.director.preproduction`
- `presentation.openmaic`
- `image.comfyx.storyboard-real`
- `comfyx.production.video.real`
- Blender Python tool

Go controller 只提交固定 capability ID + bounded input JSON；不得讓 ChatGPT ingress 傳任意 shell。

## 5. 服務與程序整合策略

「一個 Go」的意思是**一個產品/一套 binary family 的唯一控制權威**，不是把所有程式塞在同一個 `main.go`。

Go 內部 package 建議：

```text
go-runtime/
  cmd/openworker/              # canonical executable
  cmd/openworkerctl/           # temporary compatibility shim
  internal/controlcli/         # CLI parsing + bounded command contract
  internal/caseengine/         # generic case state machine
  internal/casecontroller/     # bootstrap / continue / reconcile
  internal/runtime/            # executor/process kernel
  internal/store/              # durable state
  internal/api/                # localhost API
  internal/cluster/            # multi-machine routing
  internal/ledger/             # append-only case ledger
  internal/capability/         # allowlisted leaf capability adapter
```

`openworker.exe` 可依启动参数同时承担：

- Windows service node/runtime
- local supervisor/control API
- CLI command client

短期为了避免一次大爆炸迁移，可先共用 package、保留既有 service binary；最终再合并成同一个 binary。

## 6. Case 0005 迁移顺序

### Phase G0：统一入口

- 新增 `cmd/openworker`。
- 抽出 `internal/controlcli`。
- `openworkerctl` 改为兼容 shim。
- 两者必须调用完全相同 Go 逻辑。

### Phase G1：Go-native bootstrap

- Case bootstrap 不再要求 `controller_module` / `python_exe`。
- 直接读 worklist/spec。
- materialize workspace。
- 写 `.openworker/case-supervisor-ledger.jsonl`。
- 输出 revision / ready step。

### Phase G2：Go-native continue / reconcile

- 根据 dependency + acceptance evidence 找 ready step。
- 生成 deterministic execution_id。
- 提交到 `:8848` durable queue。
- accepted receipt 写 ledger。
- status 查询可恢复 controller state。

### Phase G3：Go-native fanout / join

- character / scene / shot fanout 由 Go 直接批量提交。
- OpenWorker 只作为 process kernel / durable status authority。
- coordinator 不再由 Python 常驻。

### Phase G4：淘汰 Case Python controllers

待 Go REAL verification 完成后：

- `case0005_controller.py`
- `case0005_logged_controller.py`
- `case0005_verified_local_controller.py`
- `case0005_true_local_controller.py`
- controller-only lifecycle/recovery/fanout glue

改为 deprecated reference，最后删除。

## 8. 不再接受的架构回退

以下行为后续视为架构回退：

- 新增另一个 Case 专用 Python 主控。
- 新增第二套 CLI authority。
- GitHub Action 直接执行 Case workload。
- Case bootstrap 强制依赖 Python。
- 主控靠任意 PowerShell script 串业务流程。
- Case 状态只存在聊天或 workflow log，不落 durable ledger。
- 对同一 Case 建立多个互相不知道状态的 controller。
