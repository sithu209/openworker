# Case 0005：GitHub 短命令回執讀回缺口

時間：2026-08-19 11:04 +08:00

## 背景

目前已完成 `ChatGPT -> command-requests/oda.json -> GitHub transient command transport -> ODA self-hosted runner -> openworkerctl -> localhost:8848 -> go-tool/OpenWorker 本機總控` 的 source closure。

實測時發現新的最後一公里缺口：GitHub Action 已可把固定高階命令送進 ODA，但 transport receipt 只寫在 workflow summary / stdout。ChatGPT 端目前透過 GitHub connector 不容易穩定讀取 push-triggered workflow 的 summary，因此無法把 `case_status` 的本機真實回覆直接帶回會話。

這不是 OpenWorker 執行缺口，而是 **command transport 回執可觀測性缺口**。

## 修正原則

新增固定回執檔：

`command-results/oda.json`

由短命 GitHub Action 在成功呼叫 `openworkerctl` 後，把 transport receipt 原樣封裝並提交回 `main`。這個檔案只作為 command transport 的 read-back channel，不得成為 Case execution truth。

強制邊界：

1. `command-results/oda.json` 只能包含 request id、command、machine、case id、transport flags 與 `openworkerctl` JSON result。
2. 不得包含 arbitrary shell output、secret、token、任意本機檔案內容。
3. 不得上傳 Case artifact；PPTX/JPG/MP4 仍由 ODA 本機直接送 Google Drive。
4. `github_action_used_for_command_transport=true`。
5. `github_action_used_for_business_execution=false`。
6. workflow push path 只監聽 `command-requests/oda.json`，所以回寫 `command-results/oda.json` 不得再次觸發 command workflow，避免迴圈。
7. Case 真實進度仍以 OpenWorker / go-tool status 與本機 append-only ledger 為 authority；GitHub result 只是一個讀回鏡像。

## 目標閉環

```text
ChatGPT
  -> update command-requests/oda.json
  -> GitHub short-lived Action
  -> openworkerctl case status/continue 0005
  -> localhost:8848
  -> OpenWorker/go-tool
  -> JSON receipt
  -> command-results/oda.json
  -> ChatGPT GitHub connector read-back
```

## Case 0005 本次驗收

1. 先用 `case_status` 驗證回執讀回。
2. 能讀到 ODA 本機總控實際狀態後，再根據 `current_step / next_step / running work / failure` 決定是否再發 `case_continue`。
3. `case_continue` 只要本機 durable queue 回 `accepted=true`，GitHub Action 即結束。
4. 後續用新的 `case_status` request 追蹤，不等待舊 workflow。
5. 第一個可見成果仍是 `presentation/storyboard-text-only.pptx`，由 ODA 直接上傳 Google Drive 後由 ChatGPT Connector 審查。
