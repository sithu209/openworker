# OpenWorker 成果審查路由邊界

日期：2026-08-18

狀態：**IMPLEMENTED — REVIEW ROUTING POLICY / OWNING CI GREEN**

## 問題修正

前一批工程規範案例曾把 Google Drive 誤當成固定機器的通用 source transport，導致 `GitHub Actions → Google Drive OAuth → ODA` 被列為 KnowGraphGo corpus acceptance 的前置條件。

這個邊界不正確。

Google Drive 在 OpenWorker 的主要角色應是：**把需要 ChatGPT 視覺／多模態判斷的實體成果發布成可審查 evidence**，不是所有工作資料的通用搬運層。

## 新增政策模組

新增：`coworker/review_policy.py`

核心路由：

```text
machine-verifiable
  → local deterministic receipt
  → 不需要 Google Drive

text-only LLM judgement
  → ChatGPT text-direct
  → 不需要 Google Drive

visual / audio / layout judgement
  → ChatGPT multimodal review
  → Google Drive review bundle
```

路由依據是「品質如何判斷」，不是副檔名。

例如 PDF：

- 只驗 SHA、頁數、結構、metadata：machine-verifiable。
- 要看版面、圖表是否壓字、文字是否溢出：multimodal Drive review。

同理 PNG / MP4 也不因副檔名自動上 Drive；只有 acceptance contract 明確要求 perceptual judgement 才走 Drive。

## Fail-closed 規則

`ReviewRequirement` 必須明確宣告至少一種驗收需求：

- `machine_verifiable`
- `textual_llm_judgment`
- `visual_judgment`
- `audio_judgment`
- `layout_judgment`

若全部未宣告，`choose_review_route()` 直接拋出 `ReviewPolicyError`，不允許系統猜測「應該上 Drive」。

若 machine-verifiable 與 visual/layout 同時存在，perceptual gate 優先，仍需 multimodal review。

## 測試與 owning CI

新增：

- `tests/test_review_policy.py`
- `.github/workflows/review-policy-ci.yml`

Blocking tests 覆蓋：

1. machine-verifiable 不走 Drive。
2. text-only LLM review 不走 Drive。
3. visual/audio/layout 任一需求會走 multimodal Drive。
4. machine-verifiable + visual 仍走 multimodal。
5. 未宣告 requirement fail-closed。
6. 不以副檔名推斷 review route。

正式 owning CI：

`Review Policy CI` Run **`32072184488` = success**。

因此本批 review-routing policy 已 GREEN。

## 對既有 Drive 能力的處理

以下能力保留，不回滾：

- `coworker/review_drive.py`
- `coworker/drive_ingress.py`
- Drive publish receipt
- Drive immutable SHA/size contract
- Case 0002 / 0003 的視覺成果審查流程

但 `drive_ingress.py` 不再被視為所有案例都必須通過的 universal gate。

它是可選 transport primitive；是否使用由 acceptance/review policy 決定。

## 工程規範案例的正確分類

KnowGraphGo 13 份工程規範屬於：

```text
ReviewRequirement(machine_verifiable=True)
→ ReviewRoute.MACHINE_VERIFIABLE
→ google_drive_review_required = false
```

真正 acceptance 依據：

```text
source SHA/size/line count
→ manifest identity
→ parser / GraphData
→ SQLite import
→ every-ID re-query
→ identity-bound receipt
→ immutable revision
→ current.json
```

沒有圖像、影片、版面或其他 perceptual quality gate，因此 Google Drive OAuth failure 對這個案例的 acceptance status **沒有阻塞效果**。

## 後續案例統一原則

OpenWorker 後續案例先判斷 acceptance evidence：

```text
能由 deterministic program/receipt 驗證？
  YES → machine-verifiable，不上 Drive

需要 LLM 讀文字語意？
  YES → text-direct，不因為是 LLM 就上 Drive

需要看圖／影片／版面／聽音訊才能判斷品質？
  YES → multimodal Drive review
```

這個邊界可避免 GitHub、固定機器、Google Drive 與 ChatGPT review layer 再次不必要耦合。
