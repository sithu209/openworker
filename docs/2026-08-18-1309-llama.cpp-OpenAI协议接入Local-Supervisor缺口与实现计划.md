## 1. 本批结论

OpenWorker 已支持两种 Supervisor 控制模式，而且两者共享同一套 durable authority：

```text
external mode
= ChatGPT / Global Supervisor 主控

local mode
= 本机 llama.cpp Local Supervisor 主控
```

本机 llama.cpp 是可选接入，不是 OpenWorker 的强制依赖。未启动 llama.cpp 时，ChatGPT 仍可通过 go-tool + OpenWorker + GitHub transport 主控案例；启动 llama.cpp 后则可把本机连续观察、决策、tool-call loop 下沉到 Local Supervisor。

两种模式都必须遵守：

```text
OpenWorker durable state = 唯一状态权威
go-tool = 工具/能力/负面知识入口
CaseWorklist = canonical business progress authority
GitHub Action = transport / CI / evidence，不是业务完成权威
```

禁止 external/local 各自维护第二套 queue、PID、scheduler 或 case progress。

## 2. 双模式架构

```text
                ChatGPT / Global Supervisor
                         |   external mode
                         v
                    go-tool / OpenWorker
                         |
                         v
                 OpenWorker durable core
                         ^
                         |
                local mode（可选）
                         |
        llama.cpp <- OpenAI protocol -> Local Supervisor Host
```

切换模式不迁移 durable job。Supervisor 只决定“谁负责观察与决策”，不改变 job authority。

## 4. external mode

当 llama.cpp 未接入时：

```text
ChatGPT
-> 读 CaseWorklist / OpenWorker durable evidence
-> 问 go-tool 工具/能力/negative knowledge
-> 选择 canonical allowed capability
-> 使用 GitHub/OpenWorker transport 发起动作
-> transport ACK 后不把它当业务成功
-> 再读取 OpenWorker durable state / artifact receipt / QC
-> 决定下一步
```

这就是 Global Supervisor 模式。它与 Local Supervisor 使用同一套 contract，因此以后可从 external 切到 local，再切回来，而不丢工作。

## 5. local mode

本机 llama.cpp 通过 OpenAI-compatible endpoint（默认 `http://127.0.0.1:8080/v1`）接入：

```text
llama-server.exe
-> coworker.local_supervisor
-> OpenAI function tools
-> go-tool / OpenWorker
```

每次 Host 启动创建新的 transient `session_id`，然后先执行：

```text
supervisor_session
-> supervisor_recover
-> supervisor_attention
-> supervisor_jobs
-> cluster_agents
-> cluster_capabilities
```

模型 context 不是 authority；重启后必须重新 recover。

## 6. Supervisor System Contract

两种模式共同遵守：

- Supervisor 不是 worker；
- OpenWorker 是 job/process/queue/lock/progress/artifact/QC 的 durable authority；
- 不得自行维护第二套 PID / queue / scheduler；
- durable ACK 后不阻塞等待长任务；
- `Action completed != job succeeded`；
- fixed-machine job 不得漂移；
- failed/timed_out/stale/blocked 先查 durable state 与 negative knowledge；
- decision receipt 不保存 chain-of-thought；
- tool error 不得猜成成功。

## 8. Agent Loop

```text
messages + tools
-> OpenAI-compatible model
-> assistant tool_calls
-> Supervisor Host dispatch
-> role=tool + tool_call_id
-> model continuation
-> no tool_calls 时返回
```

`max_tool_rounds` 防无限循环。Malformed JSON、未知工具、缺参数、非法 drain mode 均 fail-closed。

## 9. 非阻塞与切换原则

无论 external 或 local：

```text
submit / dispatch
-> durable ACK
-> Supervisor 可结束当前 turn
-> 业务任务由 OpenWorker / owning tool 继续
```

因此：

```text
Local llama crash != OpenWorker job crash
ChatGPT 暂时离线 != OpenWorker job crash
Supervisor mode 切换 != 重新执行业务 job
```

切换前后都必须先查 durable state，禁止因为“新的 Supervisor 没有旧 context”而重复 submit。

## 12. 最终原则

这不是“必须把 llama.cpp 接进去”的架构，而是：

```text
OpenWorker = durable execution system
ChatGPT = 默认 Global Supervisor
llama.cpp = 可选 Local Supervisor
```

谁主控都不改变 OpenWorker / go-tool / CaseWorklist 的权威边界。
