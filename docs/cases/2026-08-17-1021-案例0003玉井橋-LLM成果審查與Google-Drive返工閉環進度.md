# 案例 0003 玉井橋：LLM 成果審查、Google Drive handoff 與返工閉環進度

時間：2026-08-17 10:21 +08:00

## 本批目標

把 OpenWorker Final Acceptance 從「機械驗收 PASS 就 accepted/delivered」改成真正的成果審查閉環：

`REAL tool execution -> mechanical reopen/check -> immutable Review Bundle -> Google Drive temporary handoff -> ChatGPT visual/semantic review -> PASS / TUNE / TOOL_GAP -> WorkLedger next revision`

## 已完成

### 1. ReviewCycle 共用能力

OpenWorker 已新增 `coworker/review_cycle.py`：

- 建立 immutable Review Bundle；
- 每個 artifact 記 SHA256 / size / logical name；
- Google Drive for desktop 同步目錄 handoff 使用 staging -> SHA tree verify -> atomic rename；
- LLM receipt 支援 PASS / TUNE / FAIL；
- TUNE 僅可修改 allowlisted parameters；
- 參數變更保存 before / after / reason / expected_effect；
- TUNE 建立 child revision，不覆寫原成果。

### 2. 工具缺口分類

OpenWorker 已新增 `coworker/review_gap.py`：

- `TUNE` = 現有工具能力足夠，只需調參；
- `TOOL_GAP` = 不是調參能解決，必須修 owning repo；
- TOOL_GAP 強制要求：`owning_repo`、`gap_capability`、`gap_description`、`verification_plan`；
- TOOL_GAP 轉成 WorkLedger `REWORK_REQUIRED`，保存診斷與修補驗收計畫。

### 3. Case 0003 mechanical -> LLM handoff

新增 `scripts/case0003_review_handoff.py`。

現在 7 個 mechanical checks：DTM / AOI / Consumer / Blender / SceneX / OS / Delivery 全 PASS 後：

1. 建立 required check `LLM Semantic Review = pending`；
2. 因 required check 尚未 passed，accepted pointer 在結構上不得移動；
3. 打包 Blender render、SceneX screenshot、SceneX evidence、Delivery HTML、mechanical acceptance state；
4. 複製到 `OPENWORKER_REVIEW_DRIVE_ROOT/<work-code>/<revision-id>`；
5. Drive 未配置或 SHA 不一致，狀態為 `WAITING_DRIVE_HANDOFF`；
6. Drive handoff 成功，狀態為 `WAITING_LLM_REVIEW`；
7. 此階段不執行 `accept_revision()` / `deliver_revision()`。

Google Drive 臨時 Review folder：`OpenWorker-ChatGPT-Review-TEMP`，folder ID：`1A4BnZEcFe2WIhcperRd4QSpxoSUN_ARR`。

### 4. ChatGPT receipt apply

新增 `scripts/case0003_apply_llm_review.py`：

- PASS -> `LLM Semantic Review=passed` -> accept revision -> delivery revision；
- TUNE -> 保存 parameter delta -> child revision -> `TUNING_REQUIRED`；
- TOOL_GAP -> strict gap classifier -> `REWORK_REQUIRED` -> owning repo repair loop；
- FAIL -> `REWORK_REQUIRED`。

曾在靜態回查抓到錯誤 API 名稱 `normalize_review_finding`，已在同批立即修成正式 `apply_review_finding()`，避免 receipt apply runtime import failure。

### 5. Case 0003 workflow 已切換

`.github/workflows/case-0003-yujing-bridge-ul7.yml` 已不再呼叫舊 `case0003_final_acceptance.py --workspace ...` 的直接 accepted/delivered 路徑。

現在改為：

- fresh SceneX REAL browse；
- `case0003_review_handoff.py`；
- terminal gate 必須是 `WAITING_LLM_REVIEW`；
- accepted/delivered pointer 若在 LLM review 前已移動，workflow 直接 fail；
- Review Bundle 同時保留 GitHub Action artifact 作備援 evidence。

Drive Desktop 本機同步根目錄由 GitHub Actions repository variable `OPENWORKER_REVIEW_DRIVE_ROOT` 提供。未設定時必須 fail-closed 到 `WAITING_DRIVE_HANDOFF`，不能假裝已上傳 Drive。

### 6. 防回退永久測試

新增 `tests/test_case0003_llm_review_gate.py`，永久鎖住：

- workflow 必須呼叫 review handoff；
- workflow 必須驗證 `WAITING_LLM_REVIEW`；
- handoff script 不得包含 accept/deliver；
- receipt apply 才是 PASS 後 accepted/delivered 的唯一 Case 0003 路徑；
- TUNE / TOOL_GAP 必須保留獨立狀態。
