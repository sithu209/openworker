## 5. Claim Agent 又發現一個常駐穩定性缺口，已修

`go-tool-runtime/cmd/gtr-work-agent/main.go` 舊行為：

- 一個 process 內有 4 個 claim goroutine slots；
- `runSlot()` 對 retryable control-plane error 會重試；
- 但任何一個 slot 發生 non-retryable error 時，錯誤送到 `errCh`；
- `main()` 收到第一個 slot error 就 `fatalf()`，整個 `gtr-work-agent.exe` 退出；
- ODA 目前 fallback runtime mode 為 `detached-wmi-process`，外層沒有 ScheduledTask 的 `RestartCount=999` 保護，因此 agent 一旦退出，4 個 claim slots 可一起永久消失。

這種設計與「安裝/REAL smoke 時 4 claim slots 正常，後續 durable work 長期 attempts=0」具有高度一致性；但在 read-only work probe 取得 agent/process/events evidence 前，仍不把它單獨宣稱為本次 pending 的唯一根因。

修復 commit：`55e0204ec1f5762c2e664feb166fd5fc175cf4f1`

新行為：

- resident mode 下每個 slot 自己被 supervision；
- slot 遇到 non-retryable error，只重啟該 slot，不殺整個 4-slot agent；
- backoff：1s → 2s → 4s → 5s；
- `--once` 模式保持既有 fail-fast 測試語義；
- 不更動 durable SQLite queue、不 clear work、不 resubmit Case 0005。
