# Case 0002～0005 現行操作契約統一更正

- 更新時間：2026-08-20（Asia/Taipei）
- 適用：Case0002、Case0003、Case0004、Case0005，以及後續從這些案例複製出的操作手冊
- 目的：避免歷史文件中的 OpenWorker / GitHub Actions / Drive Desktop 舊操作方式繼續誤導大模型

## 1. 統一現行架構

```text
ChatGPT / LLM
  -> go-tool：查方法、capability、required inputs、guidance、negative knowledge
  -> 必要時 GitHub Action 只送短密語 / trigger
  -> DirectWork：唯一 business controller / durable authority
  -> durable queue / work
  -> 本機 slot / executor / localexec，可依依賴安全並行
  -> REAL artifact + durable evidence
  -> 需要 ChatGPT 審查：drive.chatgpt.review.publish
  -> drive.file.publish-verified
  -> Google Drive upload + independent remote verification
  -> exact Drive revision identity
  -> ChatGPT review
  -> review receipt / decision
  -> PASS 才進 delivery
```

## 2. 全案例一律廢止作為「現行做法」的描述

下列內容若出現在舊案例文件，只能解讀為歷史紀錄：

- OpenWorker 是目前總控 / business scheduler；
- GitHub Actions workflow success 代表案例完成；
- self-hosted runner label 是 business routing authority；
- 一個 GitHub job 等於一個 durable business work；
- 修好工具後應優先 rerun 原 GitHub job 作 canonical recovery；
- 所有工作必須串行，一次只能一個 action；
- 把成果 copy 到 Google Drive Desktop/sync folder 就算上傳完成；
- 每個案例自行寫 Python uploader / OAuth / rclone；
- 舊 `openworker.review.publish` 或 legacy `drive.review.publish` 是普通成果給 ChatGPT 審查的預設方法；
- HTTP 200、Action success、檔案非空、SHA 存在可單獨視為 business PASS。

## 3. 並行規則

新版 DirectWork 允許：

- 不同 work；
- 依賴已滿足；
- 不共用不可重入資源；
- capability 明確允許；

則由多個 slot/executor 同時 claimed/running。

同一不可重入 work 仍維持 single active claim/lease。不得為了追求並行而重複提交相同不可重入工作。

## 4. Google Drive 給 ChatGPT 審查

普通成果發布的預設高層 capability：

```text
drive.chatgpt.review.publish
```

canonical primitive：

```text
drive.file.publish-verified
```

成功標準不是「本機 Drive 資料夾看到檔案」，而是：

```text
REAL local artifact
+ durable work completed
+ Google Drive upload
+ independent remote verification
+ exact Drive revision/file identity
+ ChatGPT 審查 exact revision
+ review receipt
```

Case0003 已留下多次 REAL Drive publication 的歷史成功證據；後續案例應把它視為可重用成功知識，而不是重新發明上傳方法。

## 7. Case0004 更正

## 8. Case0005 更正

Case0005 白雪公主的目標仍是 REAL 成果閉環；歷史 bootstrap/workflow/trigger 留作證據。

現行主線：短密語若由 GitHub Action 傳入，只是 ingress；DirectWork 必須真正建立 durable work，控制 ODA 本機 executor 生成 REAL PPTX/影片等成果。不能以 trigger/action success 代替成果完成。

需要把成果交給 ChatGPT 時，走統一 Drive review contract；必須取得 exact Drive identity，再由 ChatGPT 審查，最後才進 approval/delivery gate。
