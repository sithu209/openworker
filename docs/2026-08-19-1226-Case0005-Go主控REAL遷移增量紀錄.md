## 8. resident `/v1/cases/continue` 404 根因已定位並治本

源碼確認：`go-runtime/internal/api/case_continue.go` 原本透過 `ensureNativeCaseContinueRoute(s)` 註冊 `/v1/cases/continue`，但這個 ensure 只在 `caseBootstrap()` 內被呼叫。

結果是：

1. bootstrap 執行過後 route 存在；
2. resident service 一旦重啟，新的 `Server` 並不自動註冊 continue route；
3. 因此 bootstrap snapshot 還在，但 `/v1/cases/continue` 重新變成 404。

治本修復 commit：`dd085e99f7ec447d21e84188b21961ec4d4aacc8`

變更：resident `Server.New()` 啟動時即註冊 Go Case continue route，不再把 route 生命周期綁在 bootstrap side effect。

main 已有回歸測試 `go-runtime/internal/api/case_continue_route_test.go`：新建 Server 後不先 bootstrap，直接 POST `/v1/cases/continue`，必須進入 bounded 400 input validation，而不能是 404。

ODA resident node deploy workflow 也已加入 `go test ./internal/api -count=1` gate，避免 404 route regression 再被部署。
