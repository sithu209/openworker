# 舊案例文件閱讀與現行契約覆蓋索引

- 更新：2026-08-20（Asia/Taipei）
- 適用 repo：`liuxb99/openworker`
- 狀態：CURRENT CONTRACT INDEX

## 目的

本 repo 保留大量 2026-08-15～2026-08-19 的 REAL 案例紀錄。這些文件中的 run/job/commit/SHA/root-cause/receipt 是重要歷史證據，不應刪除；但當時的 OpenWorker、GitHub Actions、local-supervisor、Drive Desktop 操作方式已不是目前 canonical path。

大模型讀舊文件時必須先套用本索引。

## 現行權威

```text
LLM / ChatGPT
 -> go-tool 查 capability / guidance / negative knowledge
 -> GitHub Action（若需要遠端 ingress）只送短密語
 -> DirectWork durable work
 -> queue / slot / executor / localexec
 -> REAL artifact + durable evidence
 -> drive.chatgpt.review.publish
 -> drive.file.publish-verified
 -> Google Drive remote verification + exact revision identity
 -> ChatGPT review receipt
 -> delivery gate
```

## 舊名詞的現行解讀

| 舊文件文字 | 現行解讀 |
|---|---|
| OpenWorker 是總控 / Case Engine | 歷史架構；現行 business authority 是 DirectWork |
| go-tool local supervisor / :8848 queue authority | 歷史執行架構；現行 go-tool 是工具/方法/contract 查詢層 |
| GitHub runner label / workflow dispatch | 可保留為歷史 run 證據；現行 GitHub Action 只能是短密語 transport，不是 business authority |
| workflow success | 不能代表 business completion |
| WorkLedger 是目前唯一 durable authority | 歷史資料治理概念保留；現行完成判斷以 DirectWork durable work/evidence 為主，既有 ledger/revision 可作 provenance evidence |
| Drive Desktop sync handoff | 歷史失敗/過渡方法；不能作 cloud publication authority |
| openworker.review.publish / case.publish-artifacts | legacy；普通 ChatGPT 審查改用 drive.chatgpt.review.publish |
| drive.review.publish | legacy compatibility；普通單次成果審查優先 drive.chatgpt.review.publish |
| 自行 OAuth / Python uploader / rclone | 非預設；先問 go-tool，使用既有 verified Drive capability |
| 一次只能一個 business action | 過時；不同且依賴滿足、可重入安全的 durable works 可由 DirectWork 多 slot/executor 並行 |

## 完成證據

現行 business completion 至少應依工作類型取得：

- `work_id`
- accepted/queued/claimed/running/completed 或 blocked events
- claimed slot
- executor identity / PID（適用時）
- exit code
- artifact path / size / SHA256
- Drive review 時另需 remote verification + exact Drive revision/file identity
- ChatGPT review 時另需綁定 exact revision 的 review receipt

## 文件優先序

1. go-tool 現行 capability contract；
2. `2026-08-20-案例0002-0005-現行操作契約統一更正.md`；
3. 各案例 `case-worklists/*.json` 的 `directwork-case-worklist/v2` revision；
4. 各案例 2026-08-20 專用更正文檔；
5. 舊文件中的 REAL 歷史 evidence；
6. 舊文件中的操作步驟僅供考古，不得覆蓋 1～4。

## 對舊詳細手冊的規則

例如 `2026-08-17-1605-Case0003-玉井橋全流程操作手冊與Blender品質回修紀錄.md` 中的固定機器、workspace、run/job/commit/SHA、Blender root cause 等仍有效；但其中把 GitHub Runner Label、WorkLedger/OpenWorker、舊 review action 當現行操作 authority 的段落，必須按本索引重新解讀。

同理，`2026-08-17-1324-OpenWorker-Google-Drive成果發布與ChatGPT品質審查缺口.md` 中「Drive Desktop copy 不能證明雲端發布」這個教訓仍完全有效；只是解法已從 OpenWorker 自建 publish path 演進成 go-tool 指引的 `drive.chatgpt.review.publish -> drive.file.publish-verified`。

## 禁止模型做的事

- 不得因舊文件出現 OpenWorker 名稱就恢復 OpenWorker 作新 business controller。
- 不得因舊文件有 workflow run id 就把 GitHub Actions 當 completion authority。
- 不得因本機 Drive sync folder 有檔案就宣稱已供 ChatGPT 審查。
- 不得跳過 go-tool 而重新發明上傳工具。
- 不得把歷史 evidence 刪掉或改寫成沒發生過。
