## 1. 案例目的

案例 0002 不是單純做出影片，而是用真實阿拉丁神燈案例驗證：OpenWorker 能告訴大模型現在做到哪裡、下一步是什麼；go-tool 能告訴大模型應使用什麼正式工具、如何執行、如何查隊列與驗收；大模型依兩者答案操作 owning tool；成果落在固定工作目錄並帶實體 provenance；OpenWorker 再根據實體證據推進下一步。

## 2. 問題處理鐵律

遇到任何不知道、卡住、錯誤或路由問題時：

```text
先問 OpenWorker
→ 取得 durable current state / canonical next step / dependencies / allowed_actions / acceptance / assigned_host
→ 再問 go-tool
→ 取得 capability / queue admin / execution mode / owning repo / workflow / inputs / readiness / validations
→ 只有兩者都沒有答案才判定為系統缺口
→ 修真正 owning repo
→ 沿同一正式路徑重跑
```

禁止模型先猜工具、先猜隊列、先猜機器或直接繞過工具。

## 3. 每一步記錄格式

每一步至少記錄：時間、OpenWorker 回答、向 go-tool 提出的實際問題、go-tool 回答、選定 capability、owning repo/workflow/ref、canonical inputs、Action run/job/attempt/COMPUTERNAME、實體成果 path/size/SHA256、manifest/receipt、reopen/QC、OpenWorker 寫回與下一 canonical step。沒有機器證據只能標 `IMPLEMENTED / NOT LIVE VERIFIED`。
