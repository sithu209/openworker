## 1. 目的

本輪不是重新做一份 DWG，也不是重跑整個案例，而是把先前已經完成的真實 source materialization 與 `cad.open_dwg` 成果，正式納入 2026-08-17 新建立的 CaseWorklist canonical execution state。

CaseWorklist 的目的，是避免案例進度只存在聊天、GitHub Actions 歷史或人的記憶裡。從此每個 step 都必須：

```text
READY
→ RUNNING（綁 action_id + execution_id）
→ 收 evidence
→ PASS
```

若失敗：

```text
BLOCKED
→ 建 repair child
→ repair 成為唯一 canonical next step
→ 修復 + 重跑
→ repair PASS
→ parent 回 READY
→ 同一路徑重跑 parent
```

禁止手工竄改主線狀態或直接跳到後續 step。

## 11. 本輪新增的穩定手冊規則

### Rule A — discovery 與 reconciliation 分開

```text
首次 discovery:
    duplicate exact paths => BLOCKED

已 ingress 的治理重放:
    explicit prefer_existing_canonical
    canonical still must pass size/SHA/header
```

### Rule B — BLOCKED 不能手改

```text
BLOCKED work step
→ repair child
→ repair is canonical next step
→ repair PASS
→ parent READY
→ rerun parent
```

### Rule C — repair retry 必須窄權限

只能 retry `kind=repair`；不能提供 generic reset main work step。

### Rule D — Windows PowerShell 5.1 不使用 `>>` 寫 GITHUB_OUTPUT

固定 UTF-8 no BOM AppendAllText。

### Rule E — 產品 PASS 與治理 PASS 是兩層

Attempt 2 已證明 source 本體正確，但 transport failure 仍使 repair BLOCKED。

只有：

```text
physical product evidence PASS
+
CaseWorklist acceptance PASS
```

才可正式推進下一步。
