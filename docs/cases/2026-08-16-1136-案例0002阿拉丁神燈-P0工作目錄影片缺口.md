# 案例 0002 阿拉丁神燈：P0 工作目錄影片缺口

更新時間：2026-08-16 13:06 Asia/Taipei

狀態：`P0 / PASS / REAL ODAQ VERIFIED；防回歸修復驗證中`

## 問題定義

案例 0002 原 P0 卡點不是 MiniMax H3 能不能生成影片，而是 **Comfyx-Studio 正式工作目錄沒有收到生成後的 shot MP4**。

過去曾出現錯誤閉環：

`Studio → ComfyX → ComfyUI → H3 REAL MP4` 已成功，但影片只存在 ComfyUI / ComfyX output；Studio ProductionQueue item 沒有可靠帶入正式 `workspace_root`，因此 `AIGCDirectorProductionQueueExecutor.generateShot()` 無法在正式執行路徑中把影片 materialize 到工作目錄。workflow 最後再手動 `Copy-Item` 只能算驗證腳本補洞，不能算產品能力。

這個缺口已於 2026-08-16 以 ODAQ REAL Shot 1 正式閉環。

## 架構決策

案例 0002 採用兩階段 artifact contract：

`Studio canonical workspace contract`
→ `ComfyX audited execution`
→ `ComfyUI output root`
→ `REAL MP4 physical path`
→ `ComfyX execution ledger (path/size/mtime/sha256)`
→ `Studio atomic materialization`
→ `WORKSPACE_ROOT/production/shots/<shot-id>/video.mp4`

### 明確禁止

1. ComfyUI provider 猜測 Studio 的工作目錄。
2. workflow 在生成完成後用額外 `Copy-Item` 冒充產品能力。
3. 只記錄 ComfyUI filename / prompt ID，沒有 physical artifact provenance。
4. canonical artifact 還指向 ComfyUI output，而不是 Studio workspace copy。
5. 因為來源與 workspace 位於不同磁碟就改用相對路徑硬湊；跨磁碟由 Studio materializer 正常 copy + publish。

## 已實作修復

### 1. Queue 建立層正式擁有 workspace contract

`internal/service/aigc_director_automation.go`

- `DirectorQueueCreateRequest` 新增 `workspace_root`。
