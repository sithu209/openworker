## 1. OpenWorker 執行原則

本案例是 OpenWorker 的跨 repo 執行手冊，不是單一 repo 的進度摘要。後續維護或回歸時仍遵循：

1. 先讀本手冊，再讀 owning repo 的 contract/workflow/capability。
2. 一次只處理真正 blocker；不重跑已成功且昂貴的 REAL 工作。
3. 發現缺口時修真正 owning repo，再由同一路徑重跑。
4. workspace artifact 必須驗證存在、非零、bounded path，必要時核 SHA256/size/mtime。
5. 路徑與 workspace contract 必須 fail-closed，禁止 path traversal/workspace escape。
6. workflow success 不能只看總結論；產品步驟若全 skip，不算 REAL success。
7. GitHub Actions artifact quota 與產品 gate 分開判讀；physical workspace + SHA evidence 可作正式證據。
8. 真實成功後保留歷史 failure records，不抹除 audit trail。
