## 2. 新發現的本機執行缺口

### GOC4-007 — capability 有宣告，但 local executor registry 未註冊 DWG handler

檢查 `go-tool-runtime/internal/localexec/dwg_cad.go` 後確認 `DWGCADExecute` handler 已存在，具備：

- assigned_host 驗證
- local hostname 驗證
- absolute workspace 驗證
- DWG_todo checkout 驗證
- 直接呼叫 `scripts/invoke-agent-cad-local.ps1`
- 不需要 GitHub business action

但 `gtr-work-executor` 使用的 canonical registry 原本沒有註冊 DWG handler，因此 `dwg.story_index.execute.case-worklist` 即使可被 Go Case Engine dispatch，executor 仍會 fail-closed 回報 capability not registered。

修復：

- `RegisterDWGCAD()` 新增三個同源 alias：
  - `dwg.cad.execute`
  - `dwg.cad.execute.case-worklist`
  - `dwg.story_index.execute.case-worklist`
- 三個 alias 全部指向同一個 `DWGCADExecute`，不增加第二套執行邏輯。

提交：`bfe6b777e20fb1d26cec2e8dee4d57db82dc59c2`

### GOC4-008 — resident gtr-work-executor 沒有載入 DWG_TODO_ROOT

修復：

- `gtr-work-executor` 新增 `--dwg-todo-root`。
- 預設讀 `DWG_TODO_ROOT`。
- registry 啟動時正式呼叫 `RegisterDWGCAD()`。

提交：`51ff3b550b7f83d914fe848242fcf68e4fe4d97a`

### GOC4-009 — machine root authority 只自動載入 ENGINEERING_OS_ROOT

第一階段修復：把 `DWG_TODO_ROOT` 加入 `%ProgramData%\OpenWorker\machine-roots.json` 的自動載入。

提交：`b3d03de686fc8c9b5ec680d14b2efaa4bd3963f9`

第二階段加固：若 machine-roots 沒有 `DWG_TODO_ROOT`，executor 會直接讀：

`%ProgramData%\go-tool-runtime\work-agent\authorities\dwg-todo-current.json`

並只在 receipt authority=`dwg-todo` 且 root 內存在 `go.mod` 時設為 `DWG_TODO_ROOT`。

提交：`e4b0b5adf710c9c256d03cbaa82cdfddcc882a1a`

### GOC4-010 — DWG_todo canonical local wrapper 未 allowlist Story Index 方法

發現：`scripts/invoke-agent-cad-local.ps1` 原本沒有：

- `cad.build_story_index`
- `cad.render_story_viewports`

即使 go-tool executor 已註冊 alias，wrapper 仍會 fail-closed。

修復：

- 兩個 Story Index 方法正式加入 local allowlist。
- `cad.render_story_viewports` 加入 OpenCAD authority 方法集合，確保 REAL per-story PNG 使用固定 OpenCAD binary authority。

DWG_todo 提交：`2ab61ce986522267eea314098d19c0003135482a`

### GOC4-011 — durable result evidence 被包在 receipt.result，Go Case acceptance 看不到

發現：DWG local wrapper 的真實輸出為：

```text
receipt
├─ status
├─ method
├─ state
├─ result
└─ evidence_root
```

原 `DWGCADExecute` 只把整個 receipt 掛在 evidence.receipt，造成 Go Case Engine 對 `story_count`、`stories`、`revision` 等 acceptance key 無法直接驗證。

修復：

- 保留完整 `receipt`。
- 將 `receipt.result.*` promotion 到 durable `evidence.*`。
- 同時 promotion `state` 與 `evidence_root`。
- 不改寫或偽造原始 result。

提交：`f05c227a5220e1a1f87fae18631e7cadb6b2e37c`

永久測試：`TestRegisterDWGCADAliases`，提交 `1be6c02a1559ace1f5a622ab0d511d0da0160fc7`。

### GOC4-012 — 0004-045 acceptance 與實際 API 回傳契約不一致

原 revision 142 錯把尚未由 `cad.build_story_index` 產生的 `story_index_png` / `story_index_sha256` 當作 045 acceptance，因此即使 REAL build 成功也會被錯判失敗。

修復：Worklist 升級 revision `143`，045 acceptance 改成 API 真實可驗證欄位：

- `layout_id`
- `story_count`
- `stories`
- `revision`
- `state`
- `evidence_root`

每層 REAL PNG 與 SHA256 仍屬 047 的責任，不提前偽裝成 045 成果。

OpenWorker 提交：`29655f83c4c43b50fb8f6dd356c0e0ca92263494`
