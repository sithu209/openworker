# Case 0005：Python 主控遷移為 Go 原生控制器

更新時間：2026-08-19 11:26 +08:00

## 決策

Case 0005 的 control plane / orchestration 主線改為 Go 原生，不再以 `python -m coworker.case0005_*controller` 作為 bootstrap、dispatch、ledger、retry、status 的必要 runtime。

Python 僅保留在真正需要 Python 生態的 leaf capability，例如 ComfyX / OpenMAIC / Blender Python / 既有工具 adapter；這些 leaf process 由 Go controller 透過 durable local queue 啟動。

## 目前真實問題

最新 Case 0005 bootstrap job 在 Python controller 進入點之前失敗，stderr 以 CP950 解碼為「找不到網路路徑。」；stdout 為空。OpenWorker executor 本身已能建立 job/log，故控制層不應再依賴 Python module/cwd/runtime 才能啟動 Case。

## 目標架構

`ChatGPT -> openworkerctl -> go-tool :8848 -> Go Case Controller -> durable local queue -> OpenWorker/process kernel -> leaf capability`

約束：

1. GitHub Actions 仍只做 transient command transport，不做 business execution。
2. Case authority 仍是 OpenWorker + local durable ledger。
3. Go controller 直接讀 `case-worklists/0005.json` / `case-specs/0005.json`。
4. Go controller 直接維護 `.openworker/case-supervisor-ledger.jsonl`。
5. Go controller 直接做 bootstrap / ready-step scan / dependency gate / acceptance gate / durable submit / retry-safe idempotency。
6. Python controller 暫時保留作 migration reference / fallback comparison，但不再是 canonical controller。
7. 每個 leaf action 必須是固定 capability/action ID，不允許任意 shell 從 ChatGPT ingress 傳入。

## 第一批實作範圍

P0：先移除 Case bootstrap 對 Python 的依賴。

- 新增 Go `casecontroller` package。
- 解析 worklist/spec，驗證 case_id=0005、assigned_host、workspace、revision、step graph。
- materialize workspace + `.openworker`。

P1：將 dispatch_ready / step claim / durable ACK / terminal evidence reconciliation 搬到 Go。

P2：將 image/video fanout coordinator 搬到 Go；leaf capability 仍可執行 Python/ComfyX。
