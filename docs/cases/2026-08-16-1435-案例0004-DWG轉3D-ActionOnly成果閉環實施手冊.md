## 5. OpenWorker 的標準工作方式

OpenWorker 不是 case-specific 硬編碼 driver，而是專案 operator。


### 最終成果要求 A：樓層結構成果圖

每個主要樓層至少產一張可交付成果圖，視覺標準需達到使用者提供參考圖的用途：

- 不可由聊天端 image generation 生成。

若目前 `design.png` 只適合 debug、達不到交付可讀性，應在 `DWG_todo` 補正式 **structural plan result renderer**，再用 Action 重跑。

## 12. Step 05：原圖對照 / reconstruction overlay 成果圖

### 最終成果要求 B

需要產出至少一組「原始 DWG → 重建結構」對照圖，功能相當於使用者提供的第三張參考圖：

```text
原始 DWG 背景 / crop
+
重建柱 / 主梁 / 次梁 overlay
+
Story / layer / role legend 或可讀標示
```

目的不是漂亮，而是讓工程人員能快速檢查重建是否與原圖一致。

要求：

- overlay geometry 來源必須是 materialized authoritative state；
- background 必須來自同一 source DWG 的 Action render；
- 需有 source/reconstruction SHA provenance；
- 不得人工在聊天端合成。

若目前工具缺 overlay renderer，這是 owning repo `DWG_todo` 的正式缺口。

### 最終成果要求 C：整棟 3D 結構總覽


要求：

- 真正 Blender import；
- mesh count > 0；
- world bounds valid；
- render physical exists/non-zero；
- 3D render 與 GLB 共用同一 Building World Coordinates；
- 不能另做一套視覺模型。

如果目前 Blender gate 只產驗證 screenshot 而不適合工程交付，補正式 camera framing / structural presentation render tool。
