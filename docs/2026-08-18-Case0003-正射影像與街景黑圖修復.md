第三個 REAL 阻塞：後續 attempt 曾出現 go-tool readiness timeout。固定 diagnostic branch 取得 run `32092485287` 的 `gotool.stderr.log` 後確認真正原因為：

`capability fragment openworker-case0002-operator-admin.yaml: capability "openworker.case0002.operator.admin" has unsupported execution mode "queue_admin"`

這證明共享 capability registry 的單一 fragment 可以讓整個 go-tool runtime 啟動失敗，並連帶阻塞其他案例。最新版 `go-tool-runtime/main` 已由 `20f26d00` 正式支援 `queue_admin` execution mode。

同時補齊共享 runtime 的兩個平台級缺口：
- `f2790b27`：go-tool-runtime 啟動不再全域 `taskkill` 同機其他 `tool-runtime.exe`，避免 Case 0002 / 0003 或其他工作互相殺進程。
- `96e3247b`：永久測試鎖定 sibling runtime 不得被 cleanup。
- `ef9b2a3b`：新增完整 repository config load 測試，直接 `Load(config.yaml + capabilities.d)`；任何新 capability fragment 若讓整套 registry 無法載入，CI 應先失敗，不再等 REAL case 才發現。

因此 Case 0003 現在的 runtime 基線是：**完整 registry 可載入 + sibling runtime 不互殺 + Case0003 使用獨立 18848 endpoint**。

目前最新 `case0003-imagery-diagnostic` 可讀結果仍是舊 run `32092485287`，尚未被 18848 隔離後的新 UL7 run 覆寫，因此不得將新隔離方案提前記為 PASS。下一個權威結果必須來自新 diagnostic branch 回寫或實體 workspace evidence。
